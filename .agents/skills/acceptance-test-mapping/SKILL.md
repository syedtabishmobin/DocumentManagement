# Acceptance and test mapping

1. Identify the outcome, in/out scope, authority, dependencies, and linked requirement/decision IDs.
2. Write atomic observable acceptance criteria with stable IDs; include failure and unavailable states.
3. Map each criterion to developer unit/domain evidence and applicable contract, integration, authorization, security/privacy, accessibility, migration/repair, resilience/performance, mobile, AI-evaluation, and operational evidence.
4. Name independent QA ownership and environment/test-data needs.
5. Mark unknown consequential behaviour as a decision dependency, not an assumption.
6. Validate the structured item against `.agents/protocols/work-item.schema.json`.
